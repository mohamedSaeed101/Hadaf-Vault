- **Batched save, serial allocation.** `GetNextSerialAsync` keys the in-memory counter on the parent instance (`existingParents[id]` is one instance per id; `savedByLine` returns the same instance the level loop created) or the root sentinel, so roots and siblings under one parent share one counter; a new in-file parent's first child reads `GetNextProjectCode` after the parent's level was saved (DB has no children yet → `parentSerial + "01"`), and the two-digit rule (`< 10 ? "0"+n : n`) matches `GetNextCodeService.cs:35`.
- **Children of in-file parents.** `GetHierarchyLevels` indexes `depthByLine[parentLine]` with no guard, but this cannot throw: `ResolveParent` sets `ParentLineNumber` only from `fileState.ValidLineByNumber` (`ProjectImportValidator.cs:238`), which is filled only for rows that passed every check (`:197`), and only valid rows reach the handler loop. A child of an invalid line gets `ImportParentProjectNotFound` and is skipped.
- **Single transaction / rollback.** `BeginTransaction` once before the GL save; GL cost centers, each project level and the log all save inside it; three `RollBack(error)` returns plus the `catch { RollBack(); throw; }`. `PropertyManagerTransaction.BeginTransaction` moves the GL context onto the PM connection (`SetDbConnection` + `UseTransaction`), unchanged since round 1 (e2e-verified on Sabreen).
- **Cost-center pre-check.** Runs before `BeginTransaction`, one query, covers all generated numbers (not only the parent's branch); `CreateForAutoGeneration(isLastNode: false)` returns the `ParentCostCenter` wrapper and that instance is what the dictionary holds, so `costCenter.Id` after the GL save is the saved one.
- **Dropdown source.** `getParentCostCenterHasNoTransactions()` returns `CostCenterHasNoTransactionsListDto { Id, CostCenterName, CostCenterNumber }`, the fields the shell uses; `pageSize = 0` returns all. No `any` introduced.

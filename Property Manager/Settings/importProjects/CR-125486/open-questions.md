# CR-125486 — Open questions (answer at the plan gate)

Each question has a recommended answer. The plan already uses it, so an answer of "yes" means no change.

- [x] **Q1 Parent cost center for auto cost centers.** `CostCenter.CreateForAutoGeneration` needs a parent, and the import file has no such column. **Recommended:** one "parent cost center" dropdown on the import screen. It is required only when a row asks for a cost center. All the new cost centers (their kind is Q8) go under it, and each is linked to its project (`Project.CostCenterId`). This copies the Machine screen (`ParentCostCenterForMachineRentId`).
- [x] **Q2 (answered: removed from projects + properties, see [[decisions]]) «اثبات الإيراد» (ProofOfIncomeAndExpenses).** The spec says it comes from the company policy in general settings (decision 11/10), but no such setting exists. The Projects screen hard-codes 1 (`project-data.service.ts:139`). **Recommended:** use 1 = التعاقد على الوحدة, the same default as the screen. If a company setting is added later, both the screen and the import read it.
- [x] **Q3 Activity (النشاط).** BR-8 says the activity comes from the investment type, but the code has no such relation. Activity is a separate, user-maintained `Pm_ProjectActivities` list, and the template has its own optional column 23 النشاط. **Recommended:** take column 23, matched by name. Blank means no activity, the same as the screen.
- [x] **Q4 Uniqueness.** Today the screen does not check that number, name or second name are unique. The DB enforces only `ProjectSerial`. **Recommended:** the import enforces all three (BR-3 / BR-4), and the screen stays as it is (out of scope). Adding the check to the screen would be a separate CR.
- [x] **Q5 Status blank = «تخطيط».** No status is seeded, because `Pm_ProjectStatus` is maintained by the user. **Recommended:** when the cell is blank, use the tenant's status named «تخطيط» / "Planning" if one exists, otherwise leave it empty. A status the user types that is not found is an error.
- [x] **Q6 Limits (BR-13).** **Recommended:** 1000 rows and 5 MB per file.
- [x] **Q7 Menu group name.** **Recommended:** a new group «أدوات المشاريع والعقارات» / "Projects & Properties Tools" with module id 934.
- [x] **Q8 Kind of auto cost center** (from [[business-check-1]], rows 1–3). The Projects and Properties screens list only **parent** cost centers (`IsLastNode = false`) in their dropdowns. A property's cost center hangs under its project's cost center. A leaf cost center linked to a project would show as blank on the screen and could be cleared by the next save. **Recommended:**
  - Create the auto cost center as a **parent** cost center (`IsLastNode = false`) under the chosen parent, which matches the screen.
  - Give it both names: Arabic = project name, English = second-language name. This needs a small GL Logic overload.
  - The chosen parent must be an active parent cost center with no transactions. The API checks this once per import and rejects the whole import if it fails.
  - BR-9 still decides **which** projects get one (projects with no sub-projects in the file).
- [x] **Q9 Cost distribution values** (business check row 4). The code list is «بالتساوى لجميع الوحدات / نسبة لمساحة الوحدة / نسبة لسعر الوحدة». The source note's «نسبة لمساحة العقار / نسبة يدوية لكل عقار» do not exist. **Recommended:** the template accepts the code list's names, and the source note is treated as stale.

Also adopted from the business check, no answer needed:
- Arabic name matching normalises alef forms, ة/ه, ى/ي and strips tashkeel on both sides (row 5).
- A parent number that matches more than one existing project is a row error ("ambiguous"), not a guess (row 6).
- An existing leaf project that gains sub-projects from the file keeps its own cost center. The import changes no existing project (row 7).
- **KG:** `D:\Hadaf\Accflex_KG\` is not cloned on this machine. Property Manager and GL cost centers had no KG coverage, so the check ran against the code. Report the gap to the PO team.

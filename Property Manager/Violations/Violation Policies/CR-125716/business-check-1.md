## Checked and kept (no row)

The form note (source §ترتيب الشاشة) is in line 39. Pass.
- **BR-3 tiered fallback:** `AmountForOccurrence` (lines 33–35) and the four A7 cases match the source text exactly (2nd → First when 0; 3rd+ → Third, else Second, else First). BR-2 guarantees n ≥ 1, so `n ≤ 1 → First` is safe. Pass.
- **AC-4 / first amount > 0 (Q6):** the source defaults First to 0 yet makes it required; with «0 = same as previous tier» semantics a saved 0 would mean «no fine», so rejecting 0 is the only reading that keeps AC-4 meaningful. Pass (row 3 asks for the DB floor).
- **Defaults A1:** Noise, active, window 12, amounts 0, apply mode by country = source fields 4–10 and the «جديد» button row. Pass.
- **Uniqueness scope / tenancy:** no `Pm_*` table carries `BranchId` / `CompanyId`; PM master data is per tenant DB (CR-125562 check). A tenant-wide `UQ_Pm_ViolationPolicy_Code` matches `Pm_ContractClause`. No cross-tenant or cross-branch reach. Pass.
- **Delete / FK (BR-5, contract-clause half):** handler check `Pm_ContractClause.Any(FinePolicyId == id)` + the FK (row 1 for deploy safety) gives a clean message and a hard DB guard; `DeleteContractClauseCommand` has no reverse dependency. Deactivating a policy referenced by a clause is allowed (source field 6: inactive hidden from pickers; existing references stay). Pass.
- **BR-4 (editing a policy does not change recorded violations):** true by construction now; line 40 tells the violation log CR to copy the amount at record time. It also implies the log copies the apply mode and the window it used; noted for that CR, no change here. Pass.

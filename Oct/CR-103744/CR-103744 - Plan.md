# CR-103744 — ESS notifications: Implementation Plan (as shipped)

> [!info] Sources
> Ticket facts: [[CR-103744 - Source]] · Every decision: [[CR-103744 - Open Questions]] · Session record: [[CR-103744 - Session Summary 2026-10-07]] · Business notes: `accflex-docs/Payroll/5 - Wages & Salaries/EmployeeBonus`, `…/1 - Organization & Policies/VacationWorkPolicy`

> [!note] Rewritten on 2026-10-07 to describe the code as it is now
> Two designs from earlier drafts were **removed** and appear only in the phase-table history:
> - a dedupe table `PR_EmployeeNotificationLog` (D13);
> - a `TenantId` on the Logistics driver-bonus job (D11').

**Goal:** an employee with an ESS app account gets a push notification, plus a bell entry, when:

1. **a bonus is added** for them: from the bonus screen, the bonus import, or a Logistics driver bonus (D3). There is no notification on edit or delete (D4').
2. **a leave balance is added** for them: on the web screen *Vacation balance transfer* (`vacation-balance-transfer`), including its Excel import (D5, D10).
3. **they work an official holiday** and the monthly attendance sheet credits them, either as **leave days** or as a **cash allowance** (D2'). This is sent once per credit; a recalculation that changes nothing sends nothing (D13).

Each type has a company on/off switch, and all three are **on** by default (D8). The text is in the sender's culture (D7).

**Out of scope:**
- **Desktop (AccFlex_ERP):** no change (D6). Desktop bonus screens save through the API, so they notify anyway; desktop direct-SQL writes do not.
- **Deep link from the push** to a screen: follow-up CR covering Identity and the mobile app (D1).
- **UI for the switches** (D12).
- **Monthly accrual:** it is not a recorded transaction, so there is nothing to notify about.

## Architecture

- **Sending: the existing pipeline, unchanged.**
  - `IAccFlexNotificationPublisher.PublishAsync` writes `ACFX_Notifications` in the Identity DB.
  - AccessControl's Hangfire queue → `NotificationDistributer` → `PushNotificationNotifier` (FCM to `ACFX_UserMobileDevice`) and SignalR.
  - The same publish creates the bell entry (`GET api/UserNotification/GetNotifications`).
  - **No Identity or AccessControl change.**
- **Target.** `Employee.UserGuidNumber`. An empty value means no app account, so the employee is skipped silently. Only the employee themselves is targeted, never their manager or substitute.
- **New `Payroll.Service/EmployeeEventNotifications/`:**
  - **`IEmployeeEventNotificationService`** has `NotifyBonusAddedAsync(ids)`, `NotifyLeaveBalanceAddedAsync(ids)` and `NotifyHolidayWorkAsync(items)`. For each call it:
    - checks the company switch;
    - batch-loads what the text needs;
    - skips an empty GUID;
    - publishes one push per event.

    It **saves nothing** and **never throws**: each publish has its own try/catch and logs failures. It is called **after** the business save.
  - **`IEmployeeEventNotificationStore`** holds the EF queries. Reads by id use `IgnoreQueryFilters()`, so the EmployeeSecurityLevel filter cannot hide an employee in a Hangfire scope. Tenancy is per database, not a query filter.
  - **`HolidayWorkNotificationItemsBuilder`** is pure (no I/O):
    - `Build`: after recalculation, it builds one item per credit: leave days per sheet, or cash per currency.
    - `SnapshotCredits`: before recalculation, it records the existing credits, keyed by `HolidayWorkCreditKey(EmployeeId, Day, IsCash, CurrencyId)`.
    - `ExcludeUnchanged`: it keeps only credits that are new or whose value changed, compared rounded to 2 decimals.
  - Registered as scoped in `Payroll.API/Startup.cs`.
- **Holiday-work snapshot, per handler:**
  - **Calculate:** in memory, from the already-included accrued list and the policy calculations. No extra query.
  - **Update:** `EmployeeAccruedVacationList` is not included here, so the handler adds **one** batched `EmployeeAccruedvacation.AsNoTracking()` query keyed by sheet id. Cash comes from the included `PolicyCalculationList`.
- **Driver-bonus job (Hangfire).**
  - The job reaches the tenant database through its ConnectionString; no payload change (D11').
  - It notifies after `Commit()`. Before notifying, it releases the committed transaction on **both** the Payroll context and the GL context.
- **Messages.** `Payroll.Logic/NotificationInfo/NotificationMessages.cs`, with `Resource.resx`, `Resource.en.resx` and `Resource.Designer.cs`. The enum `EmployeeNotificationType` (BonusAdded, LeaveBalanceAdded, HolidayWorkLeaveCredit, HolidayWorkCashAllowance) is in `Payroll.Logic/NotificationInfo/`.
- **Settings.**
  - `SystemConfiguration` has `NotifyEmployeeOnBonus`, `NotifyEmployeeOnLeaveBalance` and `NotifyEmployeeOnHolidayWork`, set through `UpdateCompanySettings`.
  - The API is additive: the update DTO takes `bool?` (null keeps the stored value), and the details DTO returns `bool`.
  - Endpoints: `GET/PUT api/SystemConfiguration/CompanySettings`.
- **Database.** The only schema change is 3 columns on `PR_SystemConfiguration`: `BIT NOT NULL`, with named `DF_` defaults of 1. No new table.

## Notification types and text

| Type | Title ar / en | Body |
|---|---|---|
| `BonusAdded` | تم إضافة مكافأة لك / A bonus was added for you | bonus name, total + currency, date (dd/MM/yyyy), description |
| `LeaveBalanceAdded` | تم إضافة رصيد إجازات لك / Leave balance added | leave type, days, valid-from date, description |
| `HolidayWorkLeaveCredit` | تم إضافة رصيد بدل عمل في إجازة رسمية / Leave credit for working on a public holiday | days, date, holiday name |
| `HolidayWorkCashAllowance` | تم احتساب بدل عمل في إجازة رسمية / Allowance for working on a public holiday | date, holiday name, amount + currency, "paid with this month's salary" / "يصرف مع راتب الشهر" |

The notification data also carries `Url` (`ess://bonus/{id}`, `ess://leaves/{typeId}`, `ess://attendance/{yyyy-MM-dd}`) for the future deep link. The push does not carry it today.

## Rules followed / bent

- **`accflex-erp-core`:** `Result` over exceptions, layering, Release builds. Followed.
- **`hangfire-background-jobs`:** notify only after commit. Followed.
- **`accflex-erp-domain`:** bent. `EmployeeNotificationType` is a plain enum, not a static-field class.
- **`AccFlex_Cloud_Database` `db-rules.md`:** rule 5 (new columns nullable first) bent on purpose. The bits are `NOT NULL DEFAULT 1` so existing companies are opted in. Publishing is safe: the columns are added in place with no rebuild.
- **Builds:** VS 2022 **Community** MSBuild for the sqlproj; `dotnet build -c Release -p:OutDir=...` for Cloud_ERP.

## Risks and known gaps

- **R1 — notify only after the save.** All 6 call sites run after a successful save, outside any open transaction.
- **R2 — never break the business operation.** The service never throws, and a failed push is logged and dropped (at-most-once).
- **R3 — bulk sends.** A balance transfer for the whole company notifies every employee, one push each. The Hangfire queue absorbs the load; the company switch turns it off.
- **R4 — the update path may duplicate a holiday accrued row.** `UpdateAttendanceSheetForListCommand` does not include `EmployeeAccruedVacationList`, so the policy's delete misses the old row and a recalculation can leave a duplicate. This is existing behaviour, flagged and not fixed. Notifications are unaffected because they compare values.
- **R5 — existing bug, flagged.** `EmployeeBonus.UpdateEmployeeBonus` is missing a `return` before `Result.Success(this)`.
- **R6 — `Stage_Beta` itself is broken (not this CR):**
  - `Logistics.Application/Shared/MenuList/WebMenuGroup.cs:79` uses the missing `WebMenuItem.UserTransactionAuditReport` (PR 66586, fx121674);
  - `Payroll.Application.IntegrationTest` doesn't compile.
- **R7 — push limits.** FCM is set for Android only (no APNs), and the push carries title and body only, so it can't deep-link yet.
- **R8 — desktop direct-SQL paths send nothing** (D6). This is accepted and stated in the PR.

## Checked and kept (pass)

- Required fields: number, name, second name, type, country, governorate, city, currency, ≥ 1 investment type (`Property.cs:276-318`); the row checks plus inheritance cover each (currency: row 2). `PropertyNameSecondLanguage` NOT NULL (`Pm_Properties.sql:7`) is satisfied by "type second-language name + code".
- Inheritance from the project (BR-4): ownership, sales org, cost center, view, proof of income, geography, street, land number, activity, status all exist on `Pm_Project` and the screen copies the same set (sibling check "kept" §1). The spec copies server-side, so inherited values cannot drift from what the user saw.
- Leaf project (BR-1 / AC-5): `ChildrenProjects` on `Project.cs:50`; the lookup query filters and the server re-checks. Stricter than the screen (which has no such rule); no invariant relaxed.
- Sales organisation per user: `CreatePropertyCommand.cs:145-151` (`UserSalesOrganization` for `_userSession.UserId`); the spec keeps it request-level on the project sales org, which is the property sales org by inheritance. Consequence worth knowing: a user not linked to the project sales org cannot generate for it.
- Investment type subset: one id from the project list (BR-4) is a subset of what the screen allows (`Pm_PropertyInvestmentType` FK to `Pm_InvestmentType`); price forced to 0 when not بيع (BR-6) is stricter than the screen. No rule broken (ordering: row 3).
- Garage as child (BR-7): `ParentPropertyId` self-FK (`Pm_Properties.sql:55`); same project as the unit; serial = parent serial + `01` is exactly `GetNextPropertyCode(parent)` (`GetNextCodeService.cs:51-64`); the unit is saved before its garage so the parent Id and serial exist. Floor −1 fits `NoOfFloor INT`; area 15 > 0; rooms 0.
- One transaction with `SaveChanges` per unit: single bounded context (`IPropertyManagerContext`), so an explicit DB transaction on that context satisfies `accflex-erp-core.md` (prefer single-aggregate; `IApplicationTransaction` for multi-context). The serial MAX read inside the same transaction sees the rows of the batch.
- Name uniqueness: the DB has no unique index on `PropertyName` / `PropertyNameSecondLanguage` (`Pm_Properties.sql`, no EF `HasIndex` in `PropertyManager.Data`); `CannotDuplicateNameOrNameSecondLanguage` is only the mapping of the serial UQ. "Type name + code" names are unique by construction when codes are, so nothing to add.
- Type and usage as tenant lookups (Q5, Q6): `PropertyTypeId` → `Pm_ProjectType` NOT NULL FK (`Pm_Properties.sql:11,59`), `PropertyActivityId` nullable; blank usage → project activity matches the screen inheritance.
- Blank floor → required in the grid (note row 17), blank rooms → 0: matches the screen initial values; the DB defaults of 1 never apply because the entity sends a value.
- Tenant boundary: single DB per tenant (`accflex-erp-core.md`); `Pm_Properties` has no branch column; the code-exists check is per tenant DB by construction. No cross-tenant reach.
- 500-row limit (Q10), 400 ms verify debounce, module 936 (934/935 are the siblings): product choices; no rule touched.
- Skipped rows and «مش هيتعمل» rows ignored at save (BR-10/BR-11): matches the note.

### Goods-in-transit branch rule (2026-10-12, Mohamed)
"In the good receipt journal, وسيط تحويل بين المخازن should use the branch from the good issue" — **for every receipt
that uses this account**: store-to-store, management-to-management and movement-request receipts. The Cr goods in
transit line goes on the branch of the store the goods left (where the issue debited it), so the account nets to
zero per branch. The stock line and the header stay on the receiving store branch.
- `GoodReceiptDetailBase.Create/UpdateGoodReceiptDetailJournal`: optional `maybeCreditBranch` (unset = store branch).
- Receipt pocos (L2L, M2M, MR) carry `maybeGoodsInTransitBranch`; L2L falls back to the source store's branch.
- M2M handlers set it from the movement line's source store; MR create/update commands and revaluation use
  `GoodsInTransitBranchExtensions` (issue lines → `InventoryMovementDetailId` → store → branch; receipts keyed by
  `SourceDetailGUIDNumber` for L2L/M2M, `InventoryMovementDetailId` for MR).
- SQL script: receipt line 2 on the source store branch (must be a leaf branch, else the transfer is skipped).
- Verified: 7/7 transfer tests (new: receipt credits GIT on the given issue branch); full suite 875/67; script re-run
  on a scratch LocalDB — GIT nets to 0 on the source branch.
- **Old data** (2026-10-12): `Scripts/PostScripts/20261012100000_WI120880_GoodsInTransitReceiptLineOnIssueBranch.sql` moves the
  GIT credit line of existing, not voided receipt journals — management to management (GR 9 → GI 12) and movement
  request (GR 5 → GI 10) and store to store (GR 4 → GI 9) — to the issue store branch (receipt line → movement line by `InventoryMovementDetailId` or
  `SourceDetailGUIDNumber` → first issue line → store → branch; target must be a leaf branch). Stock line and header
  unchanged; re-runnable. Verified on scratch LocalDB (M2M + MR + L2L moved, voided journal untouched, 2nd run 0).

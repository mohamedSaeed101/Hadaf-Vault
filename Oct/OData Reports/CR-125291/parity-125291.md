## Method

### Legacy side (L)
- **R1 Brief:**
  - `Acc_GeneralBalance.Fill(toDate + 1 day, branchesIds, NULL, NULL, NULL)` verbatim.
  - Then the `BeforePrint` math in SQL, with `T(n) = BalanceDebit − BalanceCredit`:
    - each component `ROUND(·, ApproximateNo)` (the legacy formats `N<a>` and parses back with `Convert.ToDecimal`; SQL `ROUND` and .NET decimal `N` both round half away from zero)
    - Working Capital = R(|CA| − |CL|)
    - Invested Capital = R(R(LTA + WC))
    - Equity = R(T9 + T12); LTL = R(T10)
    - Capital Invested = R(R(EQ + LTL))
  - ApproximateNo = `SELECT TOP(1) ApproximateNo FROM Acc_SystemConfiguration`, as `GetApproximateNo()`.
- **R2 Compare:**
  - The 10 `Compare*Items` / `*ItemsBeforeDate` Fills verbatim, with `@BalanceDate = toDate + 1 day`. The BeforeDate SQL does its own `DATEADD(year,-1,…)`.
  - Prior value per line = the **first** BeforeDate row (SQL result order) of the same category with the same `SubItemName`, compared **ordinally** (`Latin1_General_BIN2`, as C# `==`); else 0.
  - Totals = sums. Summary Assets CA+LTA, NWC CA+CL, Contributed LTA+CA+CL, Summary Liabilities CL+EQ+LTL.
  - All five category headers and the four footers are emitted (PrintOnEmptyDataSource is not set; see Observations).
- **R3 FPS:**
  - The 5 `Financial_*` summary Fills verbatim (`@BalanceDate = toDate + 1 day`, `@BranchIdList`). The 4th printed column is `Net` for LTA and `DepreciationTot` again for CA/CL/Equity/LTL.
  - Layout order reproduced:
    - LTA/CA/CL: category header, then SubParentItemName groups ascending (NULL first), rows by `OrderInReport` (tie → SQL row order).
    - Equity: a header with the **first SQL row's** SubParentItemName, then the category header, rows in SQL order.
    - LTL: category header, then the first row's SubParentItemName header, rows in SQL order.
  - Capital = CA − CL, Total Investment = LTA + Capital, Investment Financing = EQ + LTL.
  - Empty categories emit nothing (see Observations).
- **R4 Cash Flow:**
  - `EXEC dbo.Acc_CashFlowReport(from 00:00, to 23:59:59.997, branches)` as deployed on each tenant.
  - Then the 4 C# rows, in the order `BeforePrint` adds them: 15 = Σ Grp≠0, then 8/11/14 = Σ per Grp, each over the proc rows only.
  - Rows matched on `Ordr` + the first word of the item name, compared on the signed `SumValue` (= TVF `Amount`; ABS and parentheses are display only).
  - The deployed proc text equals the repo `Acc_CashFlowReport.sql` on ELGHONEIM, Nakhil, daralmimar and dbselena. On buildingtech (and Faro-ehab, not used) only the Arabic literals differ (mojibake, `'` vs `’`); the logic is identical.
- **R5 Equity:**
  - English `AccountsBalances.Fill` verbatim.
  - `@accountslist` = the `GetEquityAccounts()` CSV (`EquityType IS NOT NULL AND IsLastNode = 1`, `''` when none).
  - `@JournalTypeList` = all types except 4: passed but unused by the SQL, as in MVC.
  - Compared on (`num` → RowKind, EquityType, EnglishName, ArabicName, Amount). Pivot order is not compared (D4: long rows).

### New side (N)
- **Inline TVFs (R1–R3):** the text between `RETURN (` and the final `)`, run verbatim through `sp_executesql` with the TVF parameters (`@ToDate DATE`, `@BranchList NVARCHAR(MAX)`). Values are those the backend passes: `toDate`, and a CSV or NULL.
- **Multi-statement TVFs (R4, R5):** the body between `BEGIN` and `END`, run as a batch. `DECLARE @Result TABLE (<RETURNS columns>)` is prepended and the final `RETURN;` is replaced by `SELECT * FROM @Result;`. Nothing else is substituted. Dates: from 00:00, to 23:59:59.997.

### Comparison
Both sides are projected onto `(RowType, K1..K4, V1..V3 DECIMAL(19,4), Seq)`:
- **R1:** RowType, Description, Subtotal, Total.
- **R2:** RowType, MainItemId (headers and lines), SubItemName (lines), Balance, PriorBalance. The caption text of the summary rows is not compared (D2 drops the "Summery Of  Liabilities" typo).
- **R3:** RowType, MainItemId, MainItemName (En), SubParentItemName, SubItemName, Cost, Depreciation, Net.
- **R4:** Item/Total, Ordr, first word, Amount.
- **R5:** RowKind, EquityTypeId, En/Ar name, Amount.

Checks per set: row counts; EXCEPT both ways without `Seq`; duplicate-aware EXCEPT (GROUP BY + COUNT); sums of V1..V3; TVF RowNo = 1..n; and, for R1–R4, the print order (EXCEPT both ways **with** `Seq`).

## Observations

**Empty categories (open point for P6).** `dbselena_Primary` has no account mapped to MainItemId 5 (Long-Term Liabilities).
- **Compare:** both sides emit the LTL CategoryHeader (0 / 0) and the Summary of Liabilities footer. That is the legacy sub-report with `PrintOnEmptyDataSource` left at default. Whether DevExpress really prints the header band of an empty `DetailReportBand` still needs the live MVC print (P6).
- **FPS:** both sides emit nothing for LTL (no CategoryHeader, no SubParentHeader). Legacy LTL keeps `PrintOnEmptyDataSource` at its default (true), so the live print may show a header row with a blank or 0 total. SQL cannot prove it; check in P6.
- No other tested tenant or date has an empty category.

**FPS ordering and SubParentItemName.**
- No tested tenant has more than one SubParentItemName inside LTA, CA or CL. Of the 38 db-all tenants with a balance-sheet mapping, only `buildingtech` has 2 groups in one category, and that category is Equity. So the LTA/CA/CL "regroup by SubParentItemName ASC" path (F4) is exercised only with one group.
  - With several groups the TVF sorts with the SQL collation, while DevExpress sorts the group values with .NET string comparison. The two can differ for Arabic or mixed-case names; this is not provable here.
- `buildingtech` Equity has 2 groups (`راس المال`, `ارباح وخسائر مبقاه`, in SQL order). The outer header shows the **first SQL row's** SubParentItemName, then the category header, then both rows. TVF order = legacy order (F5).
- `dbselena_Primary` has `OrderInReport` ties: LTA order 0 ×2, CA order 0 ×3, Equity order 0 ×2.
  - Legacy SQL order for ties is not deterministic. In these runs it coincided with the TVF tie-break (FPS: `BalanceSheetSubItemId`; Compare: `SubItemName`), so Order = OK.
  - On ties, the legacy print order itself can vary from run to run.

**Cash Flow.**
- Ordr 4: the deployed proc returned `Current Assets` then `Inventory` in all 15 runs. The TVF pins the same order (Seq equal).
- Start + Net change − End ≠ 0 in most sets, e.g. ELGHONEIM FY2025 2,370,702.00 and dbselena FY2025 −465,129,791.82. This is the known non-reconciliation (closing journals in the cash balances, unclassified types 11/13/14/16/17/18, parent postings), and it is the same on both sides.
- No proc row returned a NULL `SumValue` (the legacy C# would throw on one).

**Equity Changing.**
- No tested tenant has a type-12 leaf account also flagged `EquityType = 3`, so there is no double count in column 3.
- `dbselena_Primary` has no equity accounts. Legacy and TVF both return the single NetProfit row (column 3, 0.00).

**Compare.** No prior-only sub-items occurred (0 in every set), so quirk C2 ("prior-only line missing, counted in the prior total") is not exercised by data. It is coded the same way on both sides (first match by name, ordinal).

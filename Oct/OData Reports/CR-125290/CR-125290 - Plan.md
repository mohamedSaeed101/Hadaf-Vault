Parameter rules (backend):
- `revised`:
  - `"true"` → 1.
  - `"false"` → 0.
  - Anything else → NULL, which means both.
- Id lists are CSV. `''`, whitespace and `'null'` → NULL, which means all.
- `accountingPeriodId` is a required int. On a parse failure, return an empty list.
- `year` is a required 4-digit int. `month` maps exactly as the MVC controller does:
  - `"true"`: FromMonth 1, ToMonth 6, from = `year-01-01 00:00:00`, to = `year-06-30 23:59:59.997`.
  - `"false"`: FromMonth 6, ToMonth 12, from = `year-06-01`, to = `year-12-31 23:59:59.997`.
  - Anything else: FromMonth 1, ToMonth 12, from `year-01-01`, to `year-12-31 23:59:59.997`.
  - R5 takes only ToMonth. The legacy fromMonth is always 0, and the TVF hard-codes it.

### Columns

General rules:
- Every non-key column is nullable in C#.
- `RowNo` is `long`.
- Money is `DECIMAL(19,4)` → `decimal?`.

**R1 / R2** (same column set, one TVF each):
- Key and dimension columns:
  - `RowNo` BIGINT, `SortOrder` INT, `RowType` NVARCHAR(30).
  - `DimensionId` INT, `DimensionNo` NVARCHAR(50), `DimensionName` at the source width (R1 `Acc_CostCenter.CostCenterName` NVARCHAR(300), R2 `Acc_Branch.BranchName` NVARCHAR(500); no cast, no C# MaxLength). The dimension is the cost center in R1 and the branch in R2.
  - `AccountTypeId` INT, `AccountTypeName`, `AccountTypeNameArabic`.
- 10 value columns: `PeriodBalance`, `PeriodBudget`, `BudgetDiff`, `LastBalance`, `LastBalanceDiff`, `YearToPeriodBalance`, `YearToPeriodBudget`, `YearToPeriodBudgetDiff`, `LastYearToPeriodBalance`, `LastYearToPeriodBalanceDiff`.
- `RowType` values, in print order:
  - `AccountType`: one row per dimension × account type 1/2, with the values as printed (ABS).
  - `GrossProfit`: one row per dimension, the sum of the Cal* values (type 2 negated).
  - `GrossProfitPercent`: one row per dimension, the legacy % row, all 0 (D2 quirk).
  - `TotalGrossProfit`: one row over all dimensions.
  - `OtherAccountType`: the `Acc_IncomeStatment` rows for types other than 1/2, as printed.
  - `NetProfit`: one row, the sum of `Acc_IncomeStatment.Cal*`.
    - Open question 8 is whether this sum includes the type 1/2 rows that are cancelled at print time. DevExpress summaries do accumulate rows whose band print is cancelled in BeforePrint.
    - P1 confirms this against the DevExpress semantics and records the evidence.
- `SortOrder` / `RowNo` follow the print order.

**R3 / R4** (same column set):
- Columns: `RowNo`, `Section` NVARCHAR(20), `DimensionId`, `DimensionName`, `AccountTypeId`, `AccountTypeName`, `AccountTypeNameArabic`, `MonthNo` INT, `MonthName` (English full name, trimmed), `MonthNameArabic` (trimmed), `Budget`, `Actual`.
- `Section` values:
  - `Dimension` = pivot 1 (ComparisonActivityIncome / ComparisonBranchIncome). `Budget` = SubItemBudgetValueBalance, `Actual` = SubItemActualBalance.
  - `Summary` = pivot 2 (Acc_ComparisonIncomeStatment Fill / FillByBranch). `Budget` = BudgetValue, `Actual` = AcutalValue. The dimension columns are NULL.
- Values are signed, exactly as the English SQL returns them. The layout shows the detail cells as ABS, as the legacy pivot did.
- Row order: Section, DimensionName, AccountTypeId, MonthNo.

**R5**:
- Columns: `RowNo`, `RowType` NVARCHAR(30), `MainItemId` INT, `MainItemName`, `MainItemNameArabic`, `IncomeStatmentSubItemId` INT, `SubItemName`, `OrderInReport` INT, `MonthNo` INT, `MonthName`, `MonthNameArabic`, `Balance`.
- `RowType` values:
  - `SubItem`: the six category queries unioned. MainItemId runs 1..6, and each category keeps its legacy sign.
  - `GrossProfit`, `NetProfitBeforeTax`, `NetProfit`: the whole-range C# math, done in SQL. These rows have MonthNo NULL and are always emitted. The layout hides a value of 0.
- Row order: MainItemId, OrderInReport, SubItemName, MonthNo, then the 3 total rows.
